# デザインの正本は独立リポジトリ nozomiishii/design に置く

## 背景と課題

複数プロジェクトにデザインシステムを導入するにあたり、統一と差分の境界を決める。

Apple / Google / Spotify の調査から、Spotify Encore の system of systems 型を採ることにした。プリミティブトークンは全プロジェクトで共有し、セマンティックトークンは名前だけ共有して値は各プロジェクトで上書きする。

トークンの試作は [dev リポジトリの中で進めた](https://github.com/nozomiishii/dev/pull/2995)。どのプロジェクトにも属さない共有物なので、置き場が問題になった。

## 検討した選択肢

### 置き場

| 選択肢 | 評価 |
| --- | --- |
| dev の中に置き続ける | 試作はそのまま動く。dev に属さない共有物を dev から配ることになる |
| 独立リポジトリに切り出す | npm パッケージとして各プロジェクトへ配れる |

### 公開範囲

| 選択肢 | 評価 |
| --- | --- |
| private | GitHub Actions が無料枠を消費する。Storybook などの公開ホスティングも使えない |
| public | 再配布できない資産を置けない |

## 決定

デザイントークンの正本を独立リポジトリ nozomiishii/design に置く。configs と同じ npm 配布モデル `@nozomiishii/*` で各プロジェクトへ配る。

リポジトリは公開にする。次のものは置かない。

- 再配布できない有償フォント
- ロゴなどのブランド資産
- 未公開プロダクトの画面やストーリー。各プロジェクト側の private リポジトリに置く

移植は[最初の PR](https://github.com/nozomiishii/design/pull/1)で行った。

## 結果

### 良くなったこと

- レイアウトと操作を共有したまま、プロジェクトごとにブランドを分けられる

### 引き受けたコスト

- デザイン資産の一部は各プロジェクト側の private リポジトリに残る

### 保留した論点

- コンポーネント共有の ui パッケージは、トークン運用が回ってから判断する
